# 実機WAV往復の受入試験（計画・未実施）

## 原則
自作コーデック同士の往復一致は実機互換を保証しない。Windows版VJR-200、JR2Rescue等の独立実装、JR-200実機を別の観測系として扱う。テストROM・プログラム・録音の権利を確認し、無断でリポジトリやCI成果物に追加しない。

## 準備記録
機種/本体状態、OS、オーディオ機器、接続方法、再生/録音レベル、sample rate、量子化bit、チャンネル、BASICコマンド、ファイルhash、変換ツールversion/commitを記録する。接続先は実機マニュアルに従い、スピーカー用の増幅出力を入力端子に直接つながない。大音量での自動再生は行わない。

## 送信試験: Web/CLI → WAV → 実機
1. まず48kHz/16bit/mono・600baudで、小さな自作BASICとマシン語テストデータを用いる。
2. BASICはLOAD→LIST/RUNで一致を確認。マシン語はMLOAD後に当該RAM領域を比較する。画面に何かが出ただけでは合格にしない。
3. 00/FF/55/AA/00..FF、長さ1/255/256/257/512、複数ブロックを試す。
4. 2400baud、44.1kHz、複数の離れた領域を追加し、アドレス・長さ・内容を記録する。

## 受信試験: 実機 → WAV → CJR
1. 実機SAVE/MSAVEを別々に2回実行して録音する。同一録音ファイルのコピーは独立試験ではない。
2. 生WAVを保管し、変換時のchecksum不一致・検出ブロック・時刻・信頼度を記録する。
3. 2回のpayloadとアドレスが一致することを確認し、Windows基準実装でも読み込ませる。
4. ヘッダーの速度指定や予約領域の違いはバイト差分として報告する。内容が同じだからと理由なく正規化しない。

## 障害試験
切断、雑音、無音、逆相、DC offset、低レベル、クリッピング、左右の位相差、録音速度変動を試す。壊れた入力は失敗として返すか、未確定な候補を別扱いする。「救済」の名目で勝手にchecksumを書き換えて成功にしない。ステレオを無条件に平均して逆相の信号を消す実装を避ける。

## 合格記録
検体ID / 入力SHA-256 / 出力SHA-256 / 生録音の保管先 / ブロック一覧 / 比較結果 / 実機観測 / 再試験結果。実機成功と未検証ケースを別欄にする。
