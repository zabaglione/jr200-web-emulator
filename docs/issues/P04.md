## 目的
m6800系コアを移植し、周辺回路なしで実行とデバッグの基礎を検証する。

{{P03}}

## 受入記録（2026-09-22）

- VJR-200 commit `dd748995bede57da5baebc1225c7a33433aa6934`の4ファイルを
  Git blob単位で監査し、MAME commit
  `9940645188b6749e170b62c0ea86af0f440148da`の3 CPUファイルと
  BSD-3-Clause全文を照合した。
- `M6800Bus`のread/write結果としてaccess種別とwait stateを明示し、命令base
  cycleと分離してtraceへ記録する。IRQはlevel、NMIはpulse、WAIは一度だけstackする。
- endian依存PAIR unionを使わず、A/Bと16 bit値をshiftで構成する。`JRSystem`、
  Win32/TCHAR、cereal、UI、global debugger、周辺機器の直接tickは含めていない。
- 合成試験はALU/flag、分岐、stack順、JSR/RTS、SWI/RTI、reset、IRQ、NMI、
  WAI、CLI遅延、access別wait、`0xffff` wrap、全256 opcodeの有界進行を含む。
- 同じ10命令fixtureのopcode、全register、memory、base/wait/total cycleをnativeと
  Clang直接WASMで照合した。`make test`と`make sanitize`は各CTest 5/5成功、
  `make wasm-smoke`はCJR、CPU trace、JS wrapperの3試験に成功した。
- Emscripten 6.0.9の正式moduleを生成し、Node.jsからCPU C ABI versionとreset
  vectorを確認した。Playwright自動ブラウザ試験はmodule未導入で実行できなかった。

ここで合格したのはCPU単体である。JR-200の周辺回路、ROM/BASIC起動、実機cycle、
メーカーROM/フォント、保存済みWAVの内容・実機互換は未検証である。
