## 受入記録（2026-09-22）

- breakpointは命令実行前、watchpointは該当CPUアクセスを含む命令完了後に停止する。
  再開時は現在のbreakpointを1回だけ通過し、再到達時に再停止する。
- breakpoint/watchpoint各16件、命令履歴256件、CPUアクセス履歴512件の固定上限を
  実装し、400命令のnative試験でevictionと破棄件数を確認した。
- 履歴有効・無効の2台を同じcycle budgetで実行し、全メモリ、register、cycle、
  PCM queueが一致した。peekはread-sensitive I/Oと履歴を変えず、CPU readだけが
  実際の値とaccess種別を記録した。
- native/sanitizer各CTest 6/6、直接WASM/JS 4試験、Emscripten 6.0.9正式build、
  実ROMのlocalhostブラウザ操作、console error/warning 0件を確認した。
- 実装commit `f85aa1d3db234db71baf91b59779ea84aafe01df` に対するGitHub Actions
  run `35650269016`は4ジョブすべてsuccessだった。

カセット、音声、WAV変換、物理JR-200とのtiming一致はP08以降に残る。
