# P09 — 音声のWeb出力・休止復帰

## 目的
エミュレータ生成音をブラウザの音声デバイスへ安定して出力する。

## 依存
{{P08}}

計画IDはGitHub Issue番号ではない。登録時に実際の番号へ置き換える。

## 現時点の状態
2026-09-22受入完了。利用者操作式Web Audio、sample rate表示、固定PCM queue、
underrun計数、音量、ミュート、休止復帰を実装し、実ROMのJR BASIC `SOUND 440,50`で
非0 PCMがWeb Audioへ予約されることを確認した。追補として音声を既定ONの待機状態にし、
最初の起動操作で開始するよう変更した。PB6で制御するキークリックも追加した。詳細は
[P09_AUDIO_ACCEPTANCE.md](../P09_AUDIO_ACCEPTANCE.md) に記録した。

## 受入記録（2026-09-22）

- native/sanitizerで3 channel mix、clip、queue discard、cycle駆動44.1 kHzを確認した。
- 直接WASMで一括PCM値をnative期待値と照合し、fake 48 kHz Web Audio contextで明示開始、
  resampling境界、underrun、mute、pause/resume、disableを確認した。
- 正式Emscripten siteの実ROMで、明示開始前はAudioContext未作成、JR BASIC
  `SOUND 440,50`後は非0 PCM 45945 frame、peak 7000、overflow/underrun 0だった。
- ミュート、一時停止、停止後はactive sourceとPCM queueが0になった。
- 物理出力の音圧・周波数・pan計測は未実施であり、カセットWAVとは別である。
- 実装commit `904781db9c1e2cfefed6237d3d088ee171c3fe33` のActions run
  `35661382620`は4ジョブすべてsuccess。

## 追補記録（2026-09-22）

- 音声設定は既定ONだが、ページ表示だけではAudioContextを作らない。「起動」を押した同じ
  利用者gestureで開始し、ブラウザの自動再生制限を回避する。
- サービスマニュアル記載のPB6 key detection sound gateを実装した。`POKE 0,0`では無音、
  `POKE 0,64`では通常key検出ごとにクリックPCMを生成する。
- 固定VJR-200 Windows版は`KEYSOUND=64`を宣言するが、`Reg3_write`と3 channel音声出力には
  key click生成がないため、その欠落挙動は互換基準にしない。
- native/sanitizer各10/10、直接WASM 8系統、正式Emscripten、Chrome 153のbrowser smokeが
  成功した。実機音の録音比較と物理出力計測は未実施である。
- 追加reviewで、重なった別key、PB6途中無効化、AudioContext resume中の停止競合を再現して
  修正した。実AudioContextの開始／停止／再開と、fake contextの決定的PCM検査を分けた。
